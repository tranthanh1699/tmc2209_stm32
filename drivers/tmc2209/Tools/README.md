# TMC2209 for STM32 HAL (C port of janelia-arduino/TMC2209)

A plain C library for the TMC2209 on STM32 HAL. It uses the UART peripheral already generated by CubeMX. The library only includes `"main.h"`, so it works on any STM32 family.

## 1. Architecture overview

```
 ┌──────────────────────────────── Application (main.c / RTOS task) ──────────────────────────────┐
 │  move_to()  move_to_ex()  run_velocity()  stop()        set_run_current()  velocity_ramp_set()  │
 └──────────────┬──────────────────────────────────────────────────────┬───────────────────────────┘
                │                                                      │
 ┌──────────────▼──────────────┐                        ┌──────────────▼──────────────────────────┐
 │ tmc2209_motion.c            │                        │ tmc2209.c                               │
 │  - trapezoidal ramp (DDS)   │  tmc_motion_init()     │  - shadow registers (GCONF, CHOPCONF..) │
 │  - position / velocity      │ ─────────────────────▶ │  - Arduino-compatible API               │
 │  - runs in timer ISR        │  VACTUAL=0, dedge      │  - VACTUAL + software ramp              │
 └──────────────┬──────────────┘                        │  - framing, CRC8, echo, retry           │
                │ STEP / DIR (GPIO BSRR)                └──────────────┬──────────────────────────┘
                │                                                      │ tmc_bus_t (1 UART, 1..4 chips)
 ┌──────────────▼──────────────┐                        ┌──────────────▼──────────────────────────┐
 │ TIMx 20..50 kHz (CubeMX)    │                        │ HAL_UART (CubeMX)                       │
 └──────────────┬──────────────┘                        └──────────────┬──────────────────────────┘
                ▼                                                      ▼
            TMC2209 STEP/DIR pins                              TMC2209 PDN_UART pin (addr 0..3)
```

| File | Purpose |
|---|---|
| `Inc/tmc2209_port.h` | Hardware macros: tick, delay, critical section, fast GPIO writes. All can be overridden. |
| `Inc/tmc2209_reg.h` | Register map, masks/positions and default values (cross-checked against the original library). |
| `Inc/tmc2209.h`, `Src/tmc2209.c` | UART bus, driver configuration, status reads, velocity via VACTUAL. |
| `Inc/tmc2209_motion.h`, `Src/tmc2209_motion.c` | STEP/DIR pulse generator with ramps: position, velocity, and position + velocity + ramp. |
| `Examples/example_main.c` | Integration example with 3 drivers on one UART. |
| `Examples/example_position_velocity.c` | Cookbook: 11 position + velocity examples (see section 8.1). |
| `test/` | Mock HAL plus a simulated chip for host-side testing with `gcc`. |

In AUTOSAR terms, `tmc_bus_t` plays the role of the UART MCAL driver, `tmc2209_t` is like a Complex Device Driver that keeps register copies, and `tmc2209_motion` is like an SWC whose runnable executes at a fixed rate inside the timer interrupt.

## 2. Read this first

**The TMC2209 has no internal position controller** (unlike the TMC5130/TMC5160). Over UART you can only command velocity, through the `VACTUAL` register. The library therefore handles each requirement as follows:

| Requirement | How the library does it | STEP/DIR pins needed? |
|---|---|---|
| Velocity control | `tmc2209_move_at_velocity()` or `tmc2209_velocity_ramp_set()` (VACTUAL) | No |
| Velocity control with position tracking | `tmc_motion_run_velocity()` | Yes |
| Position control | `tmc_motion_move_to()` / `tmc_motion_move()` | Yes |
| Position + velocity + ramp | `tmc_motion_move_to_ex(target, vmax, accel)` | Yes |

In UART-only mode the true position is unknown. The library deliberately does not offer "position via VACTUAL", because integrating velocity over time drifts.

**UART needs VS.** The TMC2209 digital core is powered by an internal regulator fed from VS (motor supply). If only VCC_IO is powered and VM is not, the chip will not answer, and `tmc2209_init()` returns `TMC_ERR_NOT_READY`.

**Losing VS erases the whole configuration.**
- In bidirectional modes, poll `GSTAT.reset` periodically and call `tmc2209_restore_to_chip()` when it is set.
- In TX-only mode a reset cannot be detected, so call `tmc2209_init()` again whenever you know VS has been re-applied.

## 3. Wiring and the three UART modes

```
(A) TMC_UART_TX_ONLY                (B) TMC_UART_TX_RX                   (C) TMC_UART_HALF_DUPLEX

 MCU TX ──[1k]──┬── PDN_UART         MCU TX ──[1k]──┬── PDN_UART          MCU TX(OD) ──┬── PDN_UART
                │  (chips 0..3)      MCU RX ────────┘  (chips 0..3)                    │  (chips 0..3)
                                                                          3V3 ──[4k7]──┘ pull-up
 Write only.                         The MCU receives its own echo;       CubeMX: Single Wire.
 get_*() -> TMC_ERR_NO_RX            the library checks and drops it.     Library switches TX/RX itself.
```

**Several drivers on one bus:**
- Tie all PDN_UART pins to the same line.
- Give each chip its own address using MS1/MS2.
- After init, the microstep resolution comes from the register (`mstep_reg_select = 1`), so MS1/MS2 serve only as the address.

| MS1 | MS2 | Address |
|---|---|---|
| 0 | 0 | 0 |
| 1 | 0 | 1 |
| 0 | 1 | 2 |
| 1 | 1 | 3 |

For mode (C), the ST reference manual requires the single-wire TX pin to be open-drain with an external pull-up. Check your board schematic before choosing resistor values.

## 4. CubeMX configuration

| Peripheral | Setting | Notes |
|---|---|---|
| USARTx | 115200, 8N1, Asynchronous (A, B) or Single Wire (C) | TMC2209 auto-detects 9600..500k baud |
| NVIC USARTx | **Enabled** for mode (B) | The library uses `HAL_UART_Receive_IT` so no echo byte is lost |
| TIMx (basic: TIM6/TIM7) | Update interrupt at 20 kHz (e.g. 1 MHz timer clock → matching PSC, ARR = 49) | Must match `tick_hz` |
| NVIC TIMx | Enabled, higher priority (lower number) than non-urgent interrupts | Short ISR, no UART calls |
| GPIO STEP/DIR | Output push-pull, speed High | |
| GPIO EN | Output push-pull, initial level **High** | EN is active-low |

**HAL version requirement:** the HAL must keep `gState` and `RxState` separate, so that a blocking `HAL_UART_Transmit` can run while interrupt-driven reception is active. F4 HAL ≥ 1.7 and current F7/H7/G4/L4 HALs all qualify.

**Existing UART callbacks:** if your project already implements `HAL_UART_RxCpltCallback` for another UART, check `huart->Instance` so the callback does not re-arm reception on the TMC UART.

## 5. Quick start

```c
#include "tmc2209.h"
#include "tmc2209_motion.h"

tmc_bus_t    bus;
tmc2209_t    drv;
tmc_motion_t ax;

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM6) tmc_motion_tick(&ax);      // 20 kHz
}

void app_init(void)
{
    tmc_bus_init(&bus, &huart2, TMC_UART_TX_RX);          // (1) select bus mode
    tmc2209_init(&drv, &bus, 0);                           // (2) address 0, driver starts DISABLED
    tmc2209_set_hardware_enable_pin(&drv, EN_GPIO_Port, EN_Pin);
    tmc2209_set_microsteps_per_step(&drv, 16);
    tmc2209_set_run_current(&drv, 60);                     // % of max current set by Rsense
    tmc2209_enable(&drv);                                  // (3) TOFF = 3 + EN = LOW

    tmc_motion_cfg_t cfg = { STEP_GPIO_Port, STEP_Pin, DIR_GPIO_Port, DIR_Pin,
                             20000, false, true };         // 20 kHz tick, double-edge
    tmc_motion_init(&ax, &cfg, &drv);                      // (4) VACTUAL = 0, dedge on
    HAL_TIM_Base_Start_IT(&htim6);

    tmc_motion_move_to_ex(&ax, 32000, 6400, 12800);        // (5) 10 rev, 2 rev/s, 4 rev/s²
}
```

Differences from the original:

- Every function returns `tmc_status_t`. The original returns 0 on a failed read, which is indistinguishable from a real value.
- In bidirectional modes, every write is verified against its echo and retried automatically.
- Fixed a small bug in the original `setMicrostepsPerStep`, which used the unconstrained value.
- `SENDDELAY` is set to 2 automatically on bidirectional buses, as recommended when several addresses share a bus.

## 7. UART frames: real bytes and a decode exercise

```
Write : [SYNC][ADDR][REG|0x80][DATA MSB .......... LSB][CRC]
Read  : [SYNC][ADDR][REG][CRC]
Reply : [SYNC][0xFF][REG][DATA MSB .......... LSB][CRC]
CRC8  : poly 0x07, each byte processed LSB first
```

| Purpose | Bytes on the wire | Notes |
|---|---|---|
| Write GCONF = 0x1C0, addr 0 | `05 00 80 00 00 01 C0 F6` | pdn_disable, mstep_reg_select, multistep_filt |
| Write GCONF = 0x1C0, addr 2 | `05 02 80 00 00 01 C0 80` | Only the addr and CRC bytes differ |
| Read IOIN, addr 0 | `05 00 06 6F` | |
| IOIN reply | `05 FF 06 21 00 00 40 4F` | VERSION = 0x21, bit6 PDN_UART = 1 |
| Write CHOPCONF, addr 0 | `05 00 EC 14 01 00 53 59` | 0x6C \| 0x80 = 0xEC |
| VACTUAL = +4474, addr 1 | `05 01 A2 00 00 11 7A 61` | ≈ 3200 µsteps/s |
| VACTUAL = −4474, addr 1 | `05 01 A2 FF FF EE 86 F1` | Two's complement |

In mode (B), after sending `05 00 06 6F` the MCU receives 12 bytes: first the echo `05 00 06 6F`, then the reply `05 FF 06 21 00 00 40 4F`.

## 8. Ramped pulse generator (tmc2209_motion)

### Principle

A timer interrupts at a fixed rate F. On every tick:

```
 vel_q (Q32.32) ──(± acc_q per tick)──▶ integer part = inc
 phase(32 bit) += inc   ── overflow? ──▶ emit 1 step, position += dir
```

- **Speed and acceleration:** speed = inc × F / 2³² (µsteps/s). Acceleration is stored in 64 bits, so small accelerations keep enough resolution.
- **When to brake:** `ramp_steps` counts the steps taken while accelerating. Deceleration starts once `remaining distance ≤ ramp_steps`, so the ISR needs no division or floating point.
- **Changing a command mid-move:** `ramp_steps` is recomputed in thread context as (v² − v₀²)/(2a).
- **Reversing:** direction changes only happen once speed has dropped to `start_speed`. The reversal tick emits no step, which guarantees DIR setup time.

```
 speed
  vmax ┤      ┌──────────────┐            target moved behind:
       │     ╱                ╲             ┐
       │    ╱                  ╲             ╲ brake
 start ┤───╱                    ╲───          ╲___ reverse ___╱‾‾‾╲___ arrive
       └──────────────────────────▶ t
```

**Pitfall:** `tmc_motion_stop()` brakes with the axis default acceleration set by `tmc_motion_set_acceleration()`, not with the acceleration of the last command. To brake with a specific rate, use `tmc_motion_run_velocity(m, 0, accel)`.

### Speed limits

| STEP mode | Maximum speed | F = 20 kHz | F = 50 kHz |
|---|---|---|---|
| Normal pulse (`double_edge = false`) | F / 2 | 10 kHz | 25 kHz |
| Double edge (`CHOPCONF.dedge = 1`) | ≈ F | 20 kHz | 50 kHz |

**Example:** with 16 µsteps and a 200-step motor (3200 µsteps/rev), double-edge at 20 kHz gives about 6.2 rev/s ≈ 375 rpm.

**Jitter:** pulse jitter is one tick (50 µs at 20 kHz). The TMC2209 interpolates to 256 µsteps, so this jitter is usually negligible.

**ISR cost:** a few 64-bit additions and comparisons per axis. This is very light on Cortex-M4/M7; on Cortex-M0, lower F or the number of axes.

**Reducing HAL overhead:** you can call `tmc_motion_tick()` directly in `TIM6_DAC_IRQHandler` after clearing the update flag, instead of going through `HAL_TIM_IRQHandler`.

## 9. Velocity over UART (VACTUAL)

- **Units:** v[µsteps/s] = VACTUAL × f_CLK / 2²⁴. With the 12 MHz internal clock, one LSB ≈ 0.715 µsteps/s. The internal clock has some tolerance, so measure (count revolutions or read `TSTEP`) if accuracy matters.
- **STEP pin is ignored while VACTUAL ≠ 0.** `tmc_motion_init(…, drv)` sets VACTUAL = 0 for you.
- **Software ramp:** call `tmc2209_velocity_ramp_task()` every 5–20 ms. It only sends a frame when VACTUAL changes; one 8-byte frame at 115200 baud takes about 0.7 ms.

## 10. Bring-up checklist

1. Power VM first, then call `tmc2209_scan_bus()`. The returned bitmask must match the MS1/MS2 addresses you set.
2. After `tmc2209_init`, `tmc2209_is_setup_and_communicating()` must return `true`.
3. Read `IFCNT` before and after a write. It must increase by 1, which confirms a valid write.
4. Run `tmc_motion_run_velocity()` slowly and measure STEP with a scope. The frequency must match the command. In dedge mode, the square-wave frequency is half the step rate.
5. Mark the motor shaft, run `move(3200 * 10)`, and check that the motor turns exactly 10 revolutions.
6. Watch `bus.err_count`. If it keeps climbing, check the 1k resistor, the wiring and the common ground.

## 11. Limitations

- **Open loop:** lost steps are invisible to the `position` counter. StallGuard (DIAG pin, StealthChop only) can be used for homing or stall detection.
- **Symmetric profile only:** `ramp_steps` assumes acceleration equals deceleration.
- **TX-only mode** cannot detect a chip reset or a corrupted write.
- **Blocking UART calls:** functions take up to about `timeout_ms × (retries + 1)`. Never call them from an ISR.

## 12. Interview-prep Q&A

**Q1. Why does the TMC2209 need shadow registers?**
IHOLD_IRUN, COOLCONF, TPWMTHRS and others are write-only. Changing one field requires knowing the others. In TX-only mode there is also no way to read anything back.

**Q2. Where does the echo come from in TX+RX mode, and why arm reception before transmitting?**
TX goes through 1k into the same node as RX, so every transmitted byte comes back on RX. If `Receive` is only called after `Transmit` finishes, the echo bytes have already caused an overrun, because the RDR holds just one byte. Arming `Receive_IT` for 4 + 8 bytes before transmitting captures both the echo and the reply.

**Q3. What is SENDDELAY for?**
It is the delay before the chip replies, in multiples of 8 bit-times. It gives the master time to switch to receive (half-duplex). With several addresses on a bus, the datasheet recommends a value of 2 or more.

**Q4. Why fixed-tick DDS instead of reprogramming the timer period for every step (AVR446 style)?**
- **Fixed tick:** one timer can serve several axes, the ISR has deterministic run time, and no division is needed. The cost is one tick of jitter and a top speed limited by F.
- **Per-step period:** gives smoother pulses at high speed, but needs one timer per axis.

**Q5. How does `ramp_steps` replace s = v²/2a?**
Under constant acceleration from v₀, the steps travelled equal (v² − v₀²)/2a. That is exactly the distance needed to brake back to v₀ at the same rate. Counting steps is enough, with no multiplication or division in the ISR.

**Q6. What does double edge buy you, and what is the catch?**
Every STEP level change is one step, so the top speed doubles and no pulse width has to be generated. The driver's `dedge` bit must match the MCU setting; otherwise the actual step count doubles or halves.

**Q7. How do you detect a driver reset while running?**
Read `GSTAT.reset`, or check `GCONF.pdn_disable` with `is_setup_and_communicating()`. On detection, call `restore_to_chip()` and then `clear_reset()`. The mechanical position is no longer trustworthy, so re-home.

**Q8. Why can `position` (int32) be read without a critical section while `vel_q` (uint64) cannot?**
On Cortex-M a 32-bit read is a single LDR instruction, so it is atomic. A 64-bit read takes two instructions, and the ISR can fire between them.
